# Rust crates (butler-ai)

- Every source file opens with `// Spec: specs/NNN-slug/spec.md`. Every
  `Cargo.toml` carries `[package.metadata.butler] spec = "NNN-slug"`. A new
  file MUST be claimed by a spec edge in the same PR (the ownership ratchet
  refuses it otherwise, `C-002`).
- Crate boundaries are ownership boundaries (spec 001): `butler-core` is pure
  (no `tokio`, `tauri`, platform crates, clock, fs, or net; `cargo tree` is
  asserted in tests); `butler-capture`, `butler-ocr`, `butler-llm` expose one
  trait each; `butler-desktop` is the only crate that wires them.
- `unsafe` is `deny` workspace-wide. FFI in `butler-capture`, `butler-ocr`,
  `butler-desktop` uses `#[allow(unsafe_code)]` on the smallest block with a
  `// SAFETY:` comment. Never in `butler-core` or `butler-llm`.
- Errors: `thiserror` enums per crate; variants carry kinds and ids, never
  screen text, prompts, answers, or secrets (spec 015). Log with the
  `field!` allowlist macro (spec 016).
- Data types that touch user content follow their spec's freeze notes:
  `Frame` (no `Serialize`/`Clone`, zeroize), `Recognized` (no `Serialize`),
  `RedactedText` (single constructor), `Secret` (no `Debug`/`Display`).
- Tests: unit tests inline; transition tables, fixtures and property tests
  under `tests/`; fixtures are synthetic and generated by a committed
  generator.
- Verify: `make build test lint`, then `spec-spine index && spec-spine couple
  --base origin/main --head HEAD`.
